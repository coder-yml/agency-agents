# 📋 NEXUS 交接模板

> NEXUS 管道中每种类型的代理间交接的标准化模板。一致的交接可以防止上下文丢失 —— 这是多代理协调失败的首要原因。

---

## 1. 标准交接模板

用于任何代理之间的工作传递。

```markdown
# NEXUS 交接文档

## 元数据
| 字段 | 值 |
|-------|-------|
| **从** | [代理名称]（[部门]） |
| **到** | [代理名称]（[部门]） |
| **阶段** | 第 [N] 阶段 — [阶段名称] |
| **任务参考** | [来自 Sprint Prioritizer 待办列表的任务 ID] |
| **优先级** | [关键 / 高 / 中 / 低] |
| **时间戳** | [YYYY-MM-DDTHH:MM:SSZ] |

## 上下文
**项目**：[项目名称]
**当前状态**：[到目前为止已完成的内容 — 请具体说明]
**相关文件**：
- [文件/路径/1] — [包含内容]
- [文件/路径/2] — [包含内容]
**依赖项**：[此工作依赖哪些已完成的内容]
**约束条件**：[技术、时间线或资源约束]

## 交付请求
**需要什么**：[具体、可衡量的交付描述]
**验收标准**：
- [ ] [标准 1 — 可衡量]
- [ ] [标准 2 — 可衡量]
- [ ] [标准 3 — 可衡量]
**参考资料**：[指向规格、设计、先前工作的链接]

## 质量期望
**必须通过**：[此交付物的具体质量标准]
**所需证据**：[完成的证明应该是什么样的]
**传递给下一个**：[谁接收输出以及他们需要什么格式]
```

## 2. QA 反馈循环 — 通过

当 Evidence Collector 或其他 QA 代理批准一个任务时使用。

```markdown
# NEXUS QA 判定：通过 ✅

## 任务
| 字段 | 值 |
|-------|-------|
| **任务 ID** | [ID] |
| **任务描述** | [描述] |
| **开发者代理** | [代理名称] |
| **QA 代理** | [代理名称] |
| **尝试次数** | [N]/3 |
| **时间戳** | [YYYY-MM-DDTHH:MM:SSZ] |

## 判定：通过

## 证据
**截图**：
- 桌面（1920x1080）：[文件名/路径]
- 平板（768x1024）：[文件名/路径]
- 移动（375x667）：[文件名/路径]

**功能验证**：
- [x] [验收标准 1] — 已验证
- [x] [验收标准 2] — 已验证
- [x] [验收标准 3] — 已验证

**品牌一致性**：已验证 — 颜色、排版、间距与设计系统匹配
**无障碍**：已验证 — 键盘导航、对比度比、语义化 HTML
**性能**：[加载时间测量值] — 在可接受范围内

## 备注
[任何观察、未来改进的小建议或正面评价]

## 下一步操作
→ Agents Orchestrator：标记任务完成，推进到待办列表中的下一个任务
```

## 3. QA 反馈循环 — 不通过

当 Evidence Collector 或其他 QA 代理拒绝一个任务时使用。

```markdown
# NEXUS QA 判定：不通过 ❌

## 任务
| 字段 | 值 |
|-------|-------|
| **任务 ID** | [ID] |
| **任务描述** | [描述] |
| **开发者代理** | [代理名称] |
| **QA 代理** | [代理名称] |
| **尝试次数** | [N]/3 |
| **时间戳** | [YYYY-MM-DDTHH:MM:SSZ] |

## 判定：不通过

## 发现的问题

### 问题 1：[类别] — [严重程度：关键/高/中/低]
**描述**：[问题的确切描述]
**预期**：[根据验收标准应该发生什么]
**实际**：[实际发生的情况]
**证据**：[截图文件名或测试输出]
**修复说明**：[具体的、可操作的修复指示]
**要修改的文件**：[确切的文件路径]

### 问题 2：[类别] — [严重程度]
**描述**：[...]
**预期**：[...]
**实际**：[...]
**证据**：[...]
**修复说明**：[...]
**要修改的文件**：[...]

[继续列出所有发现的问题]

## 验收标准状态
- [x] [标准 1] — 已通过
- [ ] [标准 2] — 不通过（见问题 1）
- [ ] [标准 3] — 不通过（见问题 2）

## 重试说明
**给开发者代理**：
1. 仅修复上述列出的问题
2. 不要引入新功能或变更
3. 所有问题解决后重新提交 QA
4. 这是第 [N] 次尝试，最多 3 次

**如果第 3 次尝试仍失败**：任务将升级至 Agents Orchestrator
```

## 4. 升级报告

当任务超过 3 次重试时使用。

```markdown
# NEXUS 升级报告 🚨

## 任务
| 字段 | 值 |
|-------|-------|
| **任务 ID** | [ID] |
| **任务描述** | [描述] |
| **开发者代理** | [代理名称] |
| **QA 代理** | [代理名称] |
| **尝试已用尽** | 3/3 |
| **升级至** | [Agents Orchestrator / Studio Producer] |
| **时间戳** | [YYYY-MM-DDTHH:MM:SSZ] |

## 失败历史

### 第 1 次尝试
- **发现的问题**：[摘要]
- **应用的修复**：[开发者更改了什么]
- **结果**：不通过 — [为何仍然失败]

### 第 2 次尝试
- **发现的问题**：[摘要]
- **应用的修复**：[开发者更改了什么]
- **结果**：不通过 — [为何仍然失败]

### 第 3 次尝试
- **发现的问题**：[摘要]
- **应用的修复**：[开发者更改了什么]
- **结果**：不通过 — [为何仍然失败]

## 根因分析
**任务为何持续失败**：[对底层问题的分析]
**系统性问题**：[这是一次性问题还是模式问题？]
**复杂度评估**：[任务的范围是否合理？]

## 推荐的解决方案
- [ ] **重新分配**给不同的开发者代理（[推荐的代理]）
- [ ] **分解**为更小的子任务（[建议的拆分方案]）
- [ ] **修订方案** — 需要架构/设计变更
- [ ] **接受**当前状态并记录已知限制
- [ ] **推迟**到未来的冲刺

## 影响评估
**阻塞**：[此任务阻塞了哪些其他任务]
**时间线影响**：[这如何影响整体进度]
**质量影响**：[如果接受当前状态，存在哪些质量妥协]

## 需要决策
**决策者**：[Agents Orchestrator / Studio Producer]
**截止时间**：[需要何时做出决策以避免进一步延迟]
```

## 5. 阶段关卡交接

在 NEXUS 阶段之间过渡时使用。

```markdown
# NEXUS 阶段关卡交接

## 过渡
| 字段 | 值 |
|-------|-------|
| **从阶段** | 第 [N] 阶段 — [名称] |
| **到阶段** | 第 [N+1] 阶段 — [名称] |
| **关卡守门人** | [代理名称] |
| **关卡结果** | [通过 / 不通过] |
| **时间戳** | [YYYY-MM-DDTHH:MM:SSZ] |

## 关卡标准结果
| # | 标准 | 阈值 | 结果 | 证据 |
|---|-----------|-----------|--------|----------|
| 1 | [标准] | [阈值] | ✅ 通过 / ❌ 不通过 | [证据引用] |
| 2 | [标准] | [阈值] | ✅ 通过 / ❌ 不通过 | [证据引用] |
| 3 | [标准] | [阈值] | ✅ 通过 / ❌ 不通过 | [证据引用] |

## 向后传递的文档
1. [文档名称] — [在下一个阶段中的用途]
2. [文档名称] — [在下一个阶段中的用途]
3. [文档名称] — [在下一个阶段中的用途]

## 下一阶段的关键约束
- [来自本阶段发现的约束 1]
- [来自本阶段发现的约束 2]

## 下一阶段的代理激活
| 代理 | 角色 | 优先级 |
|-------|------|----------|
| [代理 1] | [在下一阶段的角色] | [立即 / 第 2 天 / 按需] |
| [代理 2] | [在下一阶段的角色] | [立即 / 第 2 天 / 按需] |

## 向后传递的风险
| 风险 | 严重程度 | 缓解措施 | 负责人 |
|------|----------|------------|-------|
| [风险] | [P0-P3] | [缓解计划] | [代理] |
```

| **冲刺目标** | [目标陈述] |
| **速率** | [计划] / [实际] 故事点 |

## 完成状态
| 任务 ID | 描述 | 状态 | QA 尝试次数 | 备注 |
|---------|-------------|--------|-------------|-------|
| [ID] | [描述] | ✅ 完成 | [N] | [备注] |
| [ID] | [描述] | ✅ 完成 | [N] | [备注] |

## 质量指标

- **已完成任务**：[X/Y]
- **已交付故事点**：[N]

## 顺延至下一个冲刺
| 任务 ID | 描述 | 原因 | 优先级 |
|---------|-------------|--------|----------|

## 回顾洞察

## 7. 事件交接

在事件响应期间使用。

```markdown
# NEXUS 事件交接

## 事件
| 字段 | 值 |
|-------|-------|
| **严重程度** | [P0 / P1 / P2 / P3] |
| **检测方** | [代理或系统] |
| **检测时间** | [时间戳] |
| **分配给** | [代理名称] |
| **状态** | [调查中 / 缓解中 / 已解决 / 事后复盘] |

## 描述
**发生了什么**：[事件的清晰描述]
**影响**：[谁/什么受到影响以及严重程度]
**时间线**：
- [HH:MM] — [事件]
- [HH:MM] — [事件]
- [HH:MM] — [事件]

## 当前状态
**受影响的系统**：[列表]
**是否有临时解决方案**：[是/否 — 如有请描述]
**预计解决时间**：[时间估计]

## 已采取的行动
1. [已采取的行动和结果]
2. [已采取的行动和结果]

## 交接上下文
**给下一个响应者**：
- [已尝试的方法]
- [尚未尝试的方法]
- [怀疑的根本原因]
- [要检查的相关日志/指标]

## 干系人沟通
**上次更新发送时间**：[时间戳]
**下次更新截止时间**：[时间戳]
**沟通渠道**：[更新发布在哪里]
```

## 使用指南

| 情况 | 使用的模板 |
|-----------|----------------|
| 将工作分配给另一个代理 | 标准交接（#1） |
| QA 批准任务 | QA 通过（#2） |
| QA 拒绝任务 | QA 不通过（#3） |
| 任务超过 3 次重试 | 升级报告（#4） |
| 阶段之间切换 | 阶段关卡交接（#5） |
| 冲刺结束 | 冲刺交接（#6） |
| 系统事件 | 事件交接（#7） |
