# MCP Memory 集成

> 使用模型上下文协议（MCP）为任何代理提供跨会话的持久记忆。

## 它能做什么

默认情况下，The Agency 中的代理每次会话都从头开始。上下文通过复制粘贴在代理和会话之间手动传递。MCP 记忆服务器改变了这一点：

- **跨会话记忆**：代理记住之前会话的决策、交付物和上下文
- **交接连续性**：当一个代理移交给另一个代理时，接收代理可以准确回忆起已完成了什么 —— 无需复制粘贴
- **失败时回滚**：当 QA 检查失败或架构决策被证明错误时，回滚到已知的良好状态而非重新开始

## 设置

你需要一个提供记忆工具的 MCP 服务器：`remember`、`recall`、`rollback` 和 `search`。将其添加到你的 MCP 客户端配置中（Claude Code、Cursor 等）：

```json
{
  "mcpServers": {
    "memory": {
      "command": "your-mcp-memory-server",
      "args": []
    }
  }
}
```

任何暴露 `remember`、`recall`、`rollback` 和 `search` 工具的 MCP 服务器都可以使用。请查看 [MCP 生态系统](https://modelcontextprotocol.io) 了解可用的实现。

## 如何为任何代理添加记忆

要增强现有代理的持久记忆，在代理的提示中添加一个**记忆集成**部分。此部分指示代理在关键时刻使用 MCP 记忆工具。

### 模式

```markdown
## 记忆集成

当你启动会话时：
- 使用你的角色和当前项目作为搜索词，从之前的会话中召回相关上下文
- 查看标记有你代理名称的任何记忆，以便从上次中断的地方继续

当你做出关键决策或完成交付物时：
- 用描述性标签（你的代理名称、项目、主题）记住决策或交付物
- 包含足够的上下文，以便未来的会话 —— 或其他代理 —— 能够理解做了什么以及为什么

当你移交给另一个代理时：
- 记住你的交付物，标记给接收代理
- 包含交接元数据：你完成了什么、待处理什么、以及下一个代理需要知道什么

当某件事失败且你需要恢复时：
- 搜索最后一个已知良好状态
- 使用 rollback 恢复到该点，而非从头开始重建
```

### 代理如何使用它

LLM 在获得这些指令时会自动使用 MCP 记忆工具：

- `remember` — 存储带有标签的决策、交付物或上下文快照
- `recall` — 按关键词、标签或语义相似性搜索相关记忆
- `rollback` — 在出错时恢复到之前的状态
- `search` — 跨会话和代理查找特定记忆

不需要对代理文件进行代码更改。不需要编写 API 调用。MCP 工具处理一切。

## 提示

- **一致地标记**：在每个记忆上使用代理名称和项目名称作为标签。这使召回变得可靠。
- **让 LLM 决定什么重要**：记忆指令是指导，而非刚性规则。LLM 将自行判断何时记住以及何时召回。
- **Rollback 是杀手级特性**：当 Reality Checker 拒绝一个交付物时，原始代理可以回滚到其最后一个检查点，而非尝试手动撤销更改。
